# 数据湖治理配置中心

离线版数据湖治理配置工具，涵盖多源接入通道、分层表结构设计、湖区分区策略、流批转换编排、元数据编目检索与资源计量管理，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `lake-govern-config:entries` 这一项，或调用 `resetModule(模块)`。

## 编排调度引擎

编排调度模块不只是翻计划状态：`启动编排`/`停止编排` 由 `frontend/src/api/orchestration.ts`
里的编排引擎接管，批次、执行记录与队列持久化在 `lake-govern-config:orchestration`（带版本号，
旧版本数据自动迁移，历史口径的占位字段按单波串行处理）。

- **分波次准入**：启动时先解析 `依赖图定义`（支持 `下游:上游1,上游2` 分段与 `上游->下游` 链式两种写法），
  用 Kahn 分层把没有前置关系的作业编入同一执行波次；只有拿到单波并发名额（`并发上限`）且所依赖结果
  已完成的作业才会产生执行记录。
- **超时与失败策略**：节点模拟耗时超过 `超时秒数` 标记为失败；`失败处理` 为「停止后续节点」时后续节点
  不再准入，为「继续后续节点」时仅跳过上游未完成的节点。
- **断点续跑**：每个名额批次落盘一次，写入中断时断点（最后完成的作业）保留，批次标记「已中断」，
  事务失败计划回到「待校验」；重试接着最后完成的作业跑，已完成的作业不重复执行。
- **防重复**：同一计划存在活动批次（运行中/已中断）时拒绝再次启动；同一作业被活动批次占用时，
  其他计划不得跨批次准入。
- **跨模块写回**：每次结论同步到调度执行队列（目标模块 batch）、待重试任务队列，并把批次结果写回
  批量转换任务状态，不只是改计划标记。
- **导出/导入**：每个计划可导出完整结果包（计划定义、分波、批次、执行记录、两类队列、批量转换任务
  结论 + 校验和）下载；导入时逐项校验完整性，校验和不匹配或缺段直接拒绝。
- **演练钩子**：计划的 `通知策略` 里写「模拟写中断」，首次启动会在第一个名额批次落盘后模拟写入中断，
  用于验证断点保留与重试续跑。

引擎离线校验（分波、并发名额、超时、失败策略、断点、去重、写回、导出导入、旧数据兼容共 13 项）：

```bash
cd frontend
npm run verify:orchestration
```
